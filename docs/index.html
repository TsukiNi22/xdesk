xdesk: remote desktop & terminalxdesk : bureau et terminal à distance

One binary for Windows and Unix: share a PC with a one time code, see / control it from a Qt viewer, a terminal, a browser or the Android app, every connection end to end TLS 1.3 with a post-quantum key exchange.Un seul binaire pour Windows et Unix : partager un PC avec un code à usage unique, le voir / contrôler depuis un viewer Qt, un terminal, un navigateur ou l'application Android, chaque connexion chiffrée de bout en bout en TLS 1.3 avec un échange de clés post-quantique.

1. Overview1. Vue d'ensemble

xdesk is one binary that shares a PC (host) or connects to one (client). The host serves, on a single TLS port, the web client, the Android application and the websocket used by every client; the clients see the screen, send the keyboard / mouse and open terminals, with the rights the host gives them.xdesk est un seul binaire qui partage un PC (hôte) ou s'y connecte (client). L'hôte sert, sur un seul port TLS, le client web, l'application Android et le websocket utilisé par tous les clients ; les clients voient l'écran, envoient clavier / souris et ouvrent des terminaux, selon les droits donnés par l'hôte.

5.3 Encrypted UDP video (native viewers, Android app)5.3 Vidéo UDP chiffrée (clients natifs, application Android)

The Qt viewer, the terminal client and the Android app get their frames over UDP on the port of the server when they reach it; everything else (control, inputs, terminals) stays on the TLS websocket, and the video goes back to it when UDP is blocked (2.5 s of unanswered hellos) or silent (4 s). The app does it in Java (UdpVideo, same datagrams, keys and checks) and hands the frames to the page through a message port given only to the pinned host's origin; the UDP target is the pinned host, never an address given by the page. Browsers have no raw UDP: they use extra websockets (5.4).Le client Qt, le client terminal et l'application Android reçoivent leurs trames en UDP sur le port du serveur quand ils l'atteignent ; tout le reste (contrôle, entrées, terminaux) reste sur la websocket TLS, et la vidéo y revient quand l'UDP est bloqué (2,5 s de hello sans réponse) ou muet (4 s). L'application le fait en Java (UdpVideo, mêmes datagrammes, clés et vérifications) et passe les trames à la page par un port de messages donné seulement à l'origine de l'hôte épinglé ; la cible UDP est l'hôte épinglé, jamais une adresse donnée par la page. Les navigateurs n'ont pas d'UDP brut : ils utilisent des websockets en plus (5.4).

5.4 Extra sockets of the web viewers5.4 Sockets en plus des clients web

One TCP connection on a far path that loses packets stays far under the link: its window shrinks at each loss. Several connections each keep their own window, so the host may ask a web viewer (browser, or the app when UDP does not get through) for up to 4 sockets: the extra ones open /lane and join with the session token of the welcome (32 random bytes, compared in constant time; a socket that names no active session with its token within 5 s is closed). A lane only carries frames and their acks: no input, control or terminal. Each frame goes to the least loaded socket (bytes still in its buffers), equal ones in turn, and the viewer acks it on that socket; a lane that drops frames in flight asks a complete frame.Une connexion TCP sur un chemin lointain qui perd des paquets reste loin sous le débit du lien : sa fenêtre rétrécit à chaque perte. Plusieurs connexions gardent chacune leur fenêtre, donc l'hôte peut demander à un client web (navigateur, ou l'application quand l'UDP ne passe pas) jusqu'à 4 sockets : les sockets en plus ouvrent /lane et rejoignent la session avec le jeton du welcome (32 octets aléatoires, comparés en temps constant ; une socket qui ne nomme pas une session active avec son jeton en 5 s est fermée). Une voie ne porte que les trames et leurs acks : ni entrée, ni contrôle, ni terminal. Chaque trame part sur la socket la moins chargée (octets encore dans ses tampons), à égalité chacune son tour, et le client l'acquitte sur cette socket ; une voie qui perd des trames en vol demande une image complète.

LanePolicy decides from the pressure the stream reports every second (share of the frame slots held back by a full window or a lowered quality): held back two windows of 2 s in a row, one socket more is tried for 5 s and kept only if it delivers 10 % more or holds back 0.15 less (else back to fewer, tried again after 15 s, doubled up to 2 min: the link itself is full); kept up for 10 s, one socket is given back (put back if it was needed). A LAN stays on one socket. XDESK_LANES=1..4 forces the count, the lanes setting turns it off.LanePolicy décide d'après la pression que le flux remonte chaque seconde (part des créneaux d'image retenus par une fenêtre pleine ou une qualité baissée) : retenu deux fenêtres de 2 s de suite, une socket de plus est essayée 5 s et gardée seulement si elle livre 10 % de plus ou retient 0,15 de moins (sinon retour à moins, nouvel essai après 15 s, doublé jusqu'à 2 min : le lien lui-même est plein) ; 10 s sans retard, une socket est rendue (remise si elle manquait). Un LAN reste sur une socket. XDESK_LANES=1..4 force le nombre, le réglage lanes le coupe.

7. Exposure7. Exposition

The LAN (and localhost) is always open while the host shares; the mode only adds one path. Exposure::refusal() classifies the peer address of every new socket (loopback, tailnet 100.64.0.0/10 / fd7a:115c:a1e0::/48, private ranges, public) and the server drops the peers of a path the mode does not open, before TLS; a mode change drops the sessions of the closed path.Le LAN (et localhost) reste ouvert tant que l'hôte partage ; le mode ajoute seulement un chemin. Exposure::refusal() classe l'adresse de chaque nouvelle connexion (loopback, tailnet 100.64.0.0/10 / fd7a:115c:a1e0::/48, plages privées, publique) et le serveur coupe, avant TLS, celles d'un chemin que le mode n'ouvre pas ; changer de mode coupe les sessions du chemin fermé.

7.1 Sharing switch and QR code7.1 Interrupteur de partage et QR code

Host::start(false) loads the identity, the registry and the tamper guard without listening; Host::setSharing() starts / stops the server, the exposure and the capture thread (a new Stream each time) and gives a new code at each start. The panel starts with the sharing off (Start sharing in green, Stop sharing in red, also in the tray and with s in the terminal panel). The QR code holds xdesk://host:port?fp=<sha256>&code=<code> (the Android app pins the certificate from it) or https://host:port/?code=<code> (web client); the app scans it with assets/scan.html served on a local https origin, the web client with BarcodeDetector or jsQR.Host::start(false) charge l'identité, le registre et la protection sans écouter ; Host::setSharing() démarre / arrête le serveur, l'exposition et le thread de capture (un nouveau Stream à chaque fois) et donne un nouveau code à chaque démarrage. Le panneau démarre partage coupé (Start sharing en vert, Stop sharing en rouge, aussi dans la zone de notification et avec s dans le panneau terminal). Le QR code contient xdesk://hôte:port?fp=<sha256>&code=<code> (l'application Android épingle le certificat à partir de lui) ou https://hôte:port/?code=<code> (client web) ; l'application le scanne avec assets/scan.html servie sur une origine https locale, le client web avec BarcodeDetector ou jsQR.
